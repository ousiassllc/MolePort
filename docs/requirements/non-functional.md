# MolePort 非機能要件

## 概要

MolePort の性能、セキュリティ、可用性、運用性に関する非機能要件を定義する。

## 性能要件

### NFR-01: デーモン起動時間

- **要件**: `moleport daemon start` からデーモンがリクエスト受付可能になるまで 1 秒以内
- **条件**: SSH config のホスト数が 50 件以下の場合
- **備考**: セッション復元・auto_connect の接続はバックグラウンドで非同期実行し、ソケット Listen を優先する

### NFR-02: CLI レスポンス時間

- **要件**: CLI コマンド発行からレスポンス表示まで 500ms 以内（ネットワーク操作を除く）
- **備考**: IPC 通信のオーバーヘッドを最小限にする。Unix ドメインソケットはローカル通信のため低遅延

### NFR-03: SSH 接続の確立

- **要件**: 接続開始からポートフォワーディング確立まで 10 秒以内
- **条件**: ネットワーク遅延が正常な環境（RTT 200ms 以下）
- **備考**: 接続処理はデーモン内でバックグラウンド実行し、CLI/TUI をブロックしない

### NFR-04: リアルタイム更新

- **要件**: メトリクス（接続時間、データ量）の TUI 表示更新間隔は 1 秒以内
- **備考**: 状態変化（接続/切断/エラー）はイベントサブスクリプションで即座に反映する

### NFR-05: 同時接続数

- **要件**: 最低 20 件の同時ポートフォワーディングを安定して管理できること
- **備考**: 各接続は独立した goroutine で管理する

### NFR-06: メモリ使用量

- **要件**: デーモンのアイドル時メモリ使用量は 50MB 以下
- **備考**: 接続数に比例した緩やかな増加は許容する。長時間稼働でのメモリリークがないこと

### NFR-07: 同時クライアント

- **要件**: 同時に 5 クライアント以上の IPC 接続を安定して処理できること
- **備考**: 各クライアント接続は独立した goroutine で処理する

## セキュリティ要件

### NFR-08: 認証情報の取り扱い

- **要件**: パスフレーズやパスワードをディスクに保存しない
- **備考**: メモリ上での保持も最小限にし、使用後は速やかにクリアする

### NFR-09: SSH config の読み取り

- **要件**: SSH config ファイルの読み取りはユーザー権限で行い、他ユーザーのファイルにアクセスしない
- **備考**: ファイルパーミッションが不適切な場合は警告を表示する

### NFR-10: 設定ファイルの保護

- **要件**: `~/.config/moleport/` 配下のファイルはパーミッション `0600`（所有者のみ読み書き可）で作成する
- **備考**: 既存ファイルのパーミッションが緩い場合は警告を表示する

### NFR-11: 通信の安全性

- **要件**: SSH プロトコルの暗号化を利用し、平文通信は行わない
- **備考**: HostKeyCallback を適切に設定し、known_hosts による検証を行う。ただし SSH config で `StrictHostKeyChecking no` が設定されているホストは検証をスキップする（F-23）

### NFR-12: Unix ソケットの保護

- **要件**: Unix ドメインソケットのパーミッションを `0600`（所有者のみアクセス可）に設定する
- **備考**: 他ユーザーからの不正な IPC 接続を防止する

### NFR-13: PID ファイルの安全性

- **要件**: PID ファイルの作成時に `flock` で排他ロックを取得し、競合起動を防止する
- **備考**: stale PID ファイルの検出と自動クリーンアップを行う

### NFR-14a: RemoteForward のデフォルトバインドアドレス

- **要件**: リモート転送（-R）のバインドアドレスはデフォルトで `127.0.0.1`（ループバック）とし、外部ネットワークからのアクセスを防止する
- **備考**: ユーザーが明示的に `0.0.0.0` や特定アドレスを指定した場合のみ、そのアドレスにバインドする。これは OpenSSH のデフォルト動作（`GatewayPorts no`）に準拠する。意図せず外部に公開されるセキュリティリスクを防止するための措置

## 可用性要件

### NFR-14: デーモンの安定稼働

- **要件**: デーモンは長時間（数日〜数週間）の連続稼働に耐えること
- **備考**: goroutine リーク、メモリリーク、ファイルディスクリプタリークがないこと

### NFR-15: 自動再接続

- **要件**: 接続断を KeepAlive 応答途絶により検知し、ジッター付き指数バックオフで自動リトライする
- **バックオフ**: 初期遅延 × (1 + 0〜10% ランダムジッター) → 倍増 → 最大遅延でキャップ
  - デフォルト初期遅延: 1s、最大遅延: 60s
- **ジッター**: 各リトライ間隔に 0〜10% のランダムジッターを付加し、複数ホスト同時切断時の thundering herd を回避する
- **上限**: デフォルト最大 10 回。設定で変更可能
- **KeepAlive 間隔**: デフォルト 30s。`reconnect.keepalive_interval` で設定変更可能
- **フォワード復元**: SSH 再接続成功後、当該ホストの全アクティブフォワードを自動的に再開する。復元に失敗したルールはエラー状態にし通知する
- **ホスト別ポリシー**: `hosts` セクションでホストごとに `max_retries`、`initial_delay`、`max_delay` をオーバーライド可能
- **ReconnectCount**: フォワードセッションごとに再接続回数を追跡し、メトリクスとして表示する
- **備考**: 再接続中も他の接続・クライアント通信に影響しないこと。パスワード認証のみのホストはクレデンシャル入力が必要なため `PendingAuth` 状態になる

### NFR-16: グレースフルシャットダウン

- **要件**: `moleport daemon stop` または SIGTERM/SIGINT で全接続をグレースフルに切断し、状態を保存する
- **タイムアウト**: 接続切断は 5 秒以内に完了すること。タイムアウト時は強制切断する
- **備考**: クライアントへの shutdown 通知を送信してから接続を切断する

### NFR-17: エラー耐性

- **要件**: 個別の SSH 接続エラーがデーモン全体をクラッシュさせないこと
- **備考**: エラーはクライアントに通知し、他の接続には影響を与えない

### NFR-18: クライアント切断耐性

- **要件**: CLI/TUI クライアントの異常切断がデーモンの動作に影響しないこと
- **備考**: クライアント切断時はサブスクリプションをクリーンアップする

## 運用性要件

### NFR-19: 対応 OS

- **要件**: CLI / TUI / headless デーモンは Linux、macOS で動作すること。デスクトップ GUI（`moleport-gui`）は Linux、macOS、Windows で動作すること
- **備考**: CLI/TUI は Go のクロスコンパイルによるシングルバイナリ（CGO 無効）で配布する。GUI は WebView（Linux: WebKitGTK 4.1、macOS: WKWebView、Windows: WebView2）に依存するため OS ごとのネイティブビルドで配布する（NFR-39, NFR-40）

### NFR-20: 依存関係

- **要件**: 外部コマンドへの依存を持たないこと（ssh コマンド不要）
- **備考**: Go の SSH ライブラリ（golang.org/x/crypto/ssh）で完結する

### NFR-21: ログ出力

- **要件**: デーモンのログをファイルに出力する機能を持つこと
- **出力先**: `~/.config/moleport/moleport.log`
- **備考**: ログレベル（debug / info / warn / error）を設定で切り替え可能。ログローテーションはユーザーの外部ツール（logrotate 等）に委ねる

### NFR-22: ターミナル互換性

- **要件**: TUI は 256 色以上をサポートするターミナルで正常に表示できること
- **備考**: True Color 対応ターミナルでの表示を推奨。最低限 16 色でも機能すること

### NFR-23: バイナリ配布

- **要件**: `moleport` のシングルバイナリを配布すること。`moleport-gui` は OS 別アーカイブとして GitHub Releases で配布すること
- **備考**: `moleport` は `go install` または `make install` で `$(go env GOPATH)/bin` にインストールする。GUI の配布形態は NFR-40 を参照

## アップデートチェック要件

### NFR-27: バージョンチェックのレスポンス時間

- **要件**: GitHub Releases API への問い合わせは 5 秒以内にタイムアウトすること
- **備考**: タイムアウト時はキャッシュ済みの結果を使用するか、チェックをスキップする。CLI/TUI の応答をブロックしない

### NFR-28: バージョンチェックのキャッシュ

- **要件**: デーモンが最新バージョン情報をメモリにキャッシュし、設定間隔（デフォルト: 24 時間）ごとに更新すること
- **備考**: ディスクへの永続化は不要。デーモン再起動時に再チェックする。キャッシュがない状態で `version.check` が呼ばれた場合は即座にチェックを実行する

### NFR-29: アップデートチェックのプライバシー

- **要件**: アップデートチェック時に個人情報やシステム情報を送信しないこと
- **備考**: GitHub API へのリクエストは `GET /repos/{owner}/{repo}/releases/latest` のみ。User-Agent ヘッダーにはアプリ名とバージョンのみを含む（例: `MolePort/v0.1.0`）。IP アドレス以外の識別情報は送信されない

### NFR-30: アップデートチェックの無効化

- **要件**: `update_check.enabled: false` でアップデートチェックを完全に無効化できること
- **備考**: 無効時はデーモンの定期チェック、CLI の表示、TUI の通知のすべてが停止する。ネットワークアクセスが制限された環境やプライバシーを重視するユーザー向け

### NFR-31: GitHub API レート制限への配慮

- **要件**: 認証なし API のレート制限（60 リクエスト/時）を超過しないこと
- **備考**: デフォルトの 24 時間間隔では問題にならない。最小間隔を 1 時間以上に制限する

## コード品質要件

### NFR-24: ファイル行数制限

- **要件**: すべてのソースファイル（テスト含む）は 300 行以内とする
- **ツール**: [Linterly](https://github.com/ousiassllc/Linterly) のデフォルト設定で検査する
- **閾値**: 300 行超過で ERROR、330 行（10% 超過）まで WARNING
- **計測方式**: `count_mode: all`（コメント・空行含む全行数）
- **除外対象**: `docs/`、自動生成ファイル（`.linterlyignore` で設定）
- **備考**: ファイルが肥大化した場合は責務に基づいてファイルを分割する

### NFR-25: ディレクトリ行数制限

- **要件**: 1 ディレクトリ内の直接配置ファイルの合計行数は 2000 行以内とする（サブディレクトリは含まない）
- **ツール**: Linterly のデフォルト設定で検査する
- **閾値**: 2000 行超過で ERROR、2200 行（10% 超過）まで WARNING
- **備考**: 超過時はサブパッケージへの分割を検討する

### NFR-26: コード品質検査の自動化

- **要件**: Linterly による行数検査を lefthook の pre-commit で自動実行する
- **備考**: 違反がある場合はコミットを拒否する。`linterly check` コマンドで手動実行も可能

## GUI 要件

### NFR-32: GUI 起動時間

- **要件**: `moleport-gui` の起動からメインウィンドウの初回描画までを 3 秒以内（デーモン引き継ぎを除く）とすること
- **備考**: 引き継ぎ時は旧デーモンの停止待ち（最大 10 秒）が加わる。内蔵デーモンの初期化（SSH config 読み込み、state 復元）はウィンドウ描画をブロックせず、復元結果はイベントで反映する

### NFR-33: GUI の資源使用量

- **要件**: ウィンドウ非表示（トレイ常駐）時の GUI プロセスのアイドル時 CPU 使用率は 1% 未満とすること
- **備考**: 非表示中は WebView へのイベント送信とライブティッカー（1 秒周期）を停止し、5 秒周期の照合（メモリ参照のみ）とトレイ更新のみ行う。ウィンドウ表示復帰時に全体を再取得する。トレイメニュー更新は変化時のみ、最短 500ms 間隔にデバウンスする

### NFR-34: GUI 通信のローカル限定

- **要件**: GUI は TCP/UDP のリッスンポートを一切開かないこと
- **備考**: フロントエンドとの通信は Wails の AssetServer（プロセス内）と Wails Events のみとする。Gin/HTTP サーバーを `127.0.0.1` でも公開しない。デーモンの IPC は従来どおり `0600` の Unix ソケット（NFR-12）のみ

### NFR-35: GUI の Web セキュリティ

- **要件**: HTML 出力は Templ の自動エスケープを使用し、ユーザー入力・SSH config 由来の値（ホスト名、ルール名、エラー文字列）を未エスケープで出力しないこと
- **要件**: レスポンスに `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'` を付与し、インラインスクリプト・外部リソース読み込みを禁止すること（Wails ランタイムの注入が CSP と両立しない場合は PoC で検証した最小限の例外のみ許可）
- **要件**: 状態変更を伴うアクションルートは `POST` / `DELETE` のみとし、WebView 内から発行されたリクエスト（Wails 起動時に生成した起動ごとのランダムトークンを `X-MolePort-Token` ヘッダーで照合）のみ受け付けること
- **備考**: AssetServer は他プロセスから到達できないが、WebView 内で表示される外部コンテンツ（ホスト名等に含まれる文字列）から意図しない状態変更が行われることを防ぐ多層防御として導入する

### NFR-36: GUI でのクレデンシャル取り扱い

- **要件**: パスワード・パスフレーズ・OTP は WebView ↔ 内蔵デーモン間でメモリ上のみで受け渡し、ログ・config.yaml・state.yaml・URL・Wails イベントペイロードに含めないこと
- **備考**: 入力フォームは `type="password"`（`Echo: true` の keyboard-interactive を除く）、`autocomplete="off"` とする。クレデンシャルの送信は `POST` ボディのみ。認証コールバック完了（成功・失敗・キャンセル・タイムアウト）後に保持バッファをゼロ化・参照を破棄する。リクエストペイロードをログ出力するミドルウェアはクレデンシャルルートを除外する（NFR-08 と同等）

### NFR-37: トレイ常駐の耐障害性

- **要件**: トレイの初期化失敗・トレイホストの不在・トレイの途中消失があっても、転送とウィンドウ操作が継続できること。トレイが利用できない間は、ウィンドウを閉じる操作を「非表示」ではなく「終了確認」にすること
- **備考**: ウィンドウが非表示で復帰手段（トレイ・Dock）がない状態を作らない。トレイ利用可否はトレイライブラリの登録完了コールバックで判定する

### NFR-38: デーモン引き継ぎの安全性

- **要件**: 引き継ぎは `daemon.shutdown`（グレースフル停止）のみで行い、強制終了（SIGKILL）を自動実行しないこと。PID ファイルの排他ロックが取得できるまで内蔵デーモンを起動しないこと
- **備考**: 引き継ぎ失敗時はエラーを明示して終了する（UC-26）。同時に 2 つのデーモンが SSH 接続・ポート Listen を行う状態を作らない

### NFR-39: GUI の対応環境

- **要件**: 以下を動作保証環境とする

| OS | 要件 |
|----|------|
| Linux | x64 / arm64。WebKitGTK 4.1（`libwebkit2gtk-4.1`）、GTK3。トレイは StatusNotifierItem（D-Bus）対応環境（GNOME は AppIndicator 拡張、KDE/XFCE 等は標準） |
| macOS | 11 以降。universal バイナリ（arm64 + amd64） |
| Windows | 10 1803 以降 / 11、x64。WebView2 ランタイム（Windows 11 は標準、Windows 10 は Wails ブートストラッパーで導入）。Unix ドメインソケット（AF_UNIX）対応のため 1803 以降が必須 |

- **備考**: Windows での内蔵デーモンは AF_UNIX ソケット（`%USERPROFILE%\.config\moleport\moleport.sock`）、LockFileEx による PID ロック、OpenSSH agent の named pipe（`\\.\pipe\openssh-ssh-agent`）に対応する。ファイルパーミッション（`0600` / `0700`）は Windows では ACL に委ね、ユーザープロファイル配下の既定 ACL（本人のみ）に依存する

### NFR-40: GUI の配布

- **要件**: GitHub Releases の同一タグに、GUI 用の OS 別アセットと SHA-256 チェックサムを添付すること
- **アセット**: `moleport-gui_<version>_linux_amd64.tar.gz` / `_linux_arm64.tar.gz`、`moleport-gui_<version>_darwin_universal.zip`（`MolePort.app` を含む）、`moleport-gui_<version>_windows_amd64.zip`、`checksums_gui.txt`
- **備考**: Wails は CGO と OS ネイティブの WebView を必要とするため、GoReleaser（CGO 無効のクロスビルド）では生成せず、GitHub Actions の OS 別ランナー（ubuntu-24.04 / ubuntu-24.04-arm / macos / windows）で `wails build` する。既存の `moleport` アーカイブとチェックサム（`checksums.txt`）は変更しない。初期リリースはコード署名・公証なし（OS の警告が表示されうることを README に明記する）

### NFR-41: GUI のテスト容易性とビルド分離

- **要件**: Wails・トレイ・WebView に依存しないコード（サービス層、HTTP ハンドラ、Templ コンポーネント、イベントブリッジ）は通常の `go test ./...` でテストでき、WebKitGTK 等のネイティブ依存なしに CI（ubuntu-latest）で実行できること
- **要件**: Wails / トレイに直接依存するパッケージはビルドタグ `gui` で分離し、既定の `go build ./...` / `go vet ./...` / golangci-lint の対象外とすること。GUI のビルド確認は専用 CI ジョブ（`-tags gui`）で OS 別に行う
- **備考**: 既存の CLI/TUI の配布ビルド（CGO 無効）が GUI 依存の影響を受けないこと。Templ の生成物（`*_templ.go`）はリポジトリにコミットし、CI で `templ generate` 後の差分がないことを検査する。生成物は Linterly の行数制限（NFR-24〜NFR-26）を超えるため、`.linterlyignore` に `*_templ.go` を追加して検査対象から除外する
